# CLAUDE.md

Контекст для роботи з цим репозиторієм.

## Що це за проєкт

Навчальний сайт з дисципліни **«Бази даних»** українською мовою, зібраний на
**MkDocs Material** і опублікований на GitHub Pages: https://shpil1993.github.io/DBTutorial/.
Зміст відповідає програмі дисципліни: 9 тем у 2 змістових модулях. Усі практичні приклади
написані на **Microsoft SQL Server (T-SQL)** і виконуються на одній тестовій базі
`UniversityDB`.

Аудиторія — студенти. Пояснення мають бути зрозумілими, а приклади — такими, щоб їх можна
було скопіювати в SSMS і одразу виконати.

## Структура

```
mkdocs.yml                 налаштування сайту; меню (nav) задається тут вручну
requirements.txt           mkdocs<2, mkdocs-material<10 (MkDocs 2.0 несумісний з Material)
.github/workflows/pages.yml  збирає сайт і публікує в гілку gh-pages при пуші в гілку за замовчуванням
docs/
  index.md                 головна: зміст курсу, як запускати приклади
  database.md              опис UniversityDB, ER-діаграма, тексти скриптів (через snippets)
  sql/01_create_database.sql   схема (перестворює БД!)
  sql/02_seed_data.sql         тестові дані (явні IDENTITY-значення)
  sql/03_knowledge_base.sql    схема kb для Теми 6 (правила, графові таблиці, фрейми, карта доріг)
  module1/topic1..6.md     Модуль 1. Основи проектування БД
  module2/topic7..9.md     Модуль 2. Мови запитів, транзакції, розподілені БД
tools/check_sql.py         виконує всі ```sql блоки сторінки на SQL Server
```

Нова сторінка має бути додана в `nav` у `mkdocs.yml` і, за потреби, у таблицю змісту в
`docs/index.md`.

## Тестова база UniversityDB

Таблиці `dbo`: `Faculty`, `Department`, `Teacher` (рекурсивний `ManagerId`),
`StudentGroup`, `Student` (сурогатний `StudentId` + природний `RecordBookNo`), `Course`
(обчислюваний `Hours`), `CoursePrerequisite` (M:N сама з собою), `Teaching`,
`Grade` (складений PK, обчислюваний `EctsGrade`), `Payment`, `AuditLog`; представлення
`vStudentGrades`. Схема `kb` — лише для Теми 6.

Особливості даних, на які спираються приклади (не змінювати без перевірки всіх тем):

- 17 студентів, 50 оцінок (5 нижче 60); оцінки генеруються формулою `55 + (StudentId*17 + TeachingId*29) % 46`;
- студент 5 (Литвиненко) відрахований, має оцінки лише за 1-й семестр;
- група 5 (ФН-24) — без студентів і без куратора;
- дисципліна 9 (DIST401) ніде не викладається;
- завідувачі кафедр (Teacher 1, 5, 8, 10) не ведуть занять;
- у 4 студентів `Email IS NULL`; контрактники мають `TuitionDebt`.

Блоки «Результат» на сторінках містять реальний вивід запитів на цих даних. Якщо
змінюєте дані чи запит — оновіть відповідний результат.

## Конвенції написання сторінок

- Мова тексту — українська; ідентифікатори в SQL — англійською (`Student`, `LastName`).
- Структура теми: розділи `## N.M. Назва` за пунктами програми → приклади → `## Контрольні питання`.
- Приклади, що виконуються, — у блоках ```` ```sql ````. Приклади, які **не можна** виконати
  на одному сервері (зв'язані сервери до інших машин, MS DTC, Full-Text Search), — у
  блоках ```` ```tsql ```` (підсвічування те саме, але `tools/check_sql.py` їх пропускає).
- Результати — у згортках `??? example "Результат"` (таблиця Markdown або ```` ```text ````).
- Сценарії з двома сеансами (Тема 8) — вкладки `=== "Сеанс 1"` / `=== "Сеанс 2"` з
  коментарями `-- Крок N`. Не використовуйте змінні T-SQL між кроками: у SSMS кожен
  виділений фрагмент — окремий пакет.
- Приклади, що змінюють дані, загортайте в `BEGIN TRAN … ROLLBACK`, якщо подальші приклади
  розраховують на вихідні дані.
- Діаграми — Mermaid (```` ```mermaid ````). Діаграми `gantt` не використовувати — у
  вузькій колонці вони нечитабельні.
- Посилання між сторінками — відносні шляхи до `.md` (`../module2/topic8.md#якір`);
  `mkdocs build --strict` перевіряє їх.

## Підводні камені T-SQL, на які вже наступали

- Кирилиця в рядках — тільки з префіксом `N'…'`; роздільник `STRING_AGG` має бути того ж
  типу, що й значення (`STRING_AGG(CAST(x AS NVARCHAR(..)), N' → ')`).
- `sqlcmd` за замовчуванням має `QUOTED_IDENTIFIER OFF` → фільтровані індекси та індексовані
  представлення падають. Скрипти починаються з `SET QUOTED_IDENTIFIER ON`; `check_sql.py`
  запускає `sqlcmd -I`.
- `THROW`, `ROLLBACK` у тригері та помилки компіляції **переривають пакет** — після прикладу
  з очікуваною помилкою ставте `GO`, інакше наступні оператори не виконаються.
- Об'єкти, створені в тому самому пакеті (індекс, зв'язаний сервер), не видно під час
  компіляції пакета — розділяйте `GO`.
- Тимчасові таблиці (`#WM`, `#UniversalRelation`) живуть у сеансі; tempdb може мати інше
  правило сортування → для рядкових стовпців `COLLATE DATABASE_DEFAULT`.
- `SELECT … INTO` успадковує `IDENTITY`; `CAST` прибирає його, але робить стовпець
  `NULL`-абельним — краще явний `CREATE TABLE`.
- `CHOOSE(…NEWID()…)` повертає `NULL` (вираз обчислюється кілька разів) — використовуйте
  детерміновані вирази.
- Зарезервовані слова як псевдоніми (`National`) — помилка синтаксису.
- Параметр `EXEC` не може бути виразом (`@Level + 1`) — спершу в змінну.

## Збирання сайту

```bash
pip install -r requirements.txt
mkdocs serve                 # локальний перегляд http://127.0.0.1:8000
mkdocs build --strict        # те саме, що в CI; має проходити без попереджень
```

Mermaid завантажується з unpkg.com; у хмарній пісочниці цей хост заблоковано, тому
діаграми там не рендеряться (на GitHub Pages — рендеряться). Синтаксис можна перевірити
локальною копією `mermaid` з npm через `mermaid.parse` у Playwright.

## Перевірка SQL

Кожну зміну SQL-прикладів перевіряйте на справжньому SQL Server у Docker:

```bash
# якщо Docker-демон не запущено (хмарна сесія): dockerd > /dev/null 2>&1 &
docker run -d --name mssql -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD='Test_Passw0rd!' \
  -p 1433:1433 mcr.microsoft.com/mssql/server:2022-latest     # або: docker start mssql

python3 tools/check_sql.py docs/module1/topic4.md          # одна сторінка
python3 tools/check_sql.py docs/module1/topic*.md docs/module2/topic*.md
python3 tools/check_sql.py docs/module2/topic7.md --blocks 22,23 -v   # вивід окремих блоків
```

Скрипт перестворює `UniversityDB` перед кожною сторінкою і виконує кожен блок окремим
сеансом. Позначка `[ERR]` очікувана для блоків, які **навмисно** демонструють помилку,
і для блоків, що залежать від тимчасової таблиці з попереднього блоку. Поточний еталон:

| Сторінка | Блоки з очікуваним `[ERR]` |
|----------|---------------------------|
| module1/topic1.md | 8 |
| module1/topic2.md | 2 (тимчасова таблиця з блоку 1), 4, 6 |
| module1/topic4.md | 4 |
| module1/topic6.md | 6, 7 (тимчасова `#WM` з блоку 5) |
| module2/topic7.md | 22, 23, 26, 28 |
| module2/topic8.md | 3 |
| module2/topic9.md | 10 |

Блоки, залежні від сеансу, перевіряйте разом (склейте через `GO` в один файл).
Двосеансові сценарії Теми 8 перевіряються двома паралельними `docker exec -i … sqlcmd`
з паузами між кроками.
